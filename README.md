# 千幕万象V2-导演剪辑版


🎬 一个 SillyTavern 第三方界面扩展，做你故事的**幕后导演**：埋线推演、递送创作灵感，不设定向日程与线性叙事路径，不替User做选择，最大化叙事自由度与演变弹性。

## ✨ 它能做什么

### 本次开发节点 · v1.59.369

- 镜头台「每层最少／最多插图」现支持 1–6 张，独立于「同时生成数」（仍为 1–4）。新装默认仍为最多3张、同时2张；旧配置保持原来的有效范围，升级不会把旧越界值变成更多自动生成额度。只有明确选择5–6张，或导入完整有效的新版数量设置，才启用扩展范围。
- 六镜走同一套叙事取景、提示表达、镜组风格匹配和提交账本，不拆成额外叙事调用。正常提取仍为两阶段、合计最多3次修复；镜组不改变镜头数，每个自动镜头仍只生成一张，NAI串行保护和造物之眼单独自动额度不变。
- 流式已出画面、后续补图和终稿共用原计划与额度；六镜顺序按正文而非返回顺序，保存/归档/恢复不丢第5、6镜。输入/来源变化与失败处理沿用原保护，不自动改投、重绘或重试收费请求。
- 已配置六镜时，更多镜头可能增加用户原选渠道的调用和生成费用；数量由用户显式设置。启用后请各端同步更新并刷新ST。回退前请完整备份并先处理在途任务：v368及更早版本仍仅支持四镜，不能作为新版六镜任务的继续执行器；回退代码不等于将六镜资料安全降级。
- 此为隔离实现和回归，不冒称实际模型语义、画质、ST/手机或两云验收完成。R2-08仍0/4、Phase1未完成、Phase2冻结，没有生产部署或真实收费调用。

### 🎭 幕外 —— 番外小剧场

- 🔒 **绝不污染正文** · 仅读取当前聊天作为背景参考，内容独立成篇，既不写入正文，也不纳入推演体系，正篇与番外互不干扰。

- 🪞 **同源生图网关** · 浏览器只请求千幕服务端插件，由插件向官方接口或自定义中转发起请求；API Key 不写入日志、数据包或聊天正文。
- 🧭 **模型选择可进可退** · 官方常用模型可直接选择；自定义或第三方中转可拉取模型、查看接口全部模型，也可手动填写模型 ID 兜底。
- 🎞️ **生成队列** · 任务最多 8 项且严格串行，可单独移除等待项或放弃活动任务收片；切换聊天后不会把旧任务误写进新聊天。
- 🎞️ **正文穿插** · 可把成片挂在当前回复或指定楼层之后；图片是正文显示层的独立兄弟节点，不改消息原文，不进入配音与正文正则扫描。
- 📹 **楼层快捷取镜** · 每条非系统正文都提供分镜入口，只把该层文本与锚点带入镜头台，不会因误触直接发起计费生成。
- 🔖 **自定义样式** · 各模型分别保存连接预设和参数样式，不跨供应商混用；成片也可把原提示词与参数安全载回镜头台复用。

- 🩺 **连接预检** · 通过千幕网关检查当前接口、密钥与模型；ComfyUI 会验证服务和 API Workflow，不用收费生图代替连接测试。
- 🧰 **不替用户定画质** · Model、尺寸、Steps、CFG、Seed、Sampler 与 Scheduler 保留模型原有名称，不内置强制画质方案。
- 🧭 **按能力显示参数** · 参数区跟随当前模型切换；不支持的 Seed、Steps、反向提示词或参考图能力不会显示成无效控件。
- 🪞 **人物一致性** · 通用外观档案可参与画面整理；支持参考图的模型可直接传入档案图片，ComfyUI 则通过含 `%qianmu_reference%` 的 API Workflow 接收。

- 📦 **分镜数据打包** · 一次迁移形象档案、参数样式、日志和本聊天成片；尽力内嵌图片并在新端交由 SillyTavern 落盘，始终排除 API Key。

### ST 升级与核心文件边界

千幕不要求覆盖 ST 的 `public/index.html`、`public/scripts/openai.js`、`public/scripts/power-user.js`、`public/scripts/world-info.js`、官方 Logo 或语言文件。前端放在第三方扩展目录，服务端放在独立插件目录；安装器只在备份后启用服务插件配置，不替换 ST 核心源码。

官方接口兼容以 [ST 1.19.0](https://github.com/SillyTavern/SillyTavern/releases/tag/1.19.0) 及其 [扩展上下文](https://github.com/SillyTavern/SillyTavern/blob/1.19.0/public/scripts/st-context.js) 为核对基线。旧版本缺少相关接口时保留只读兜底，不注入脚本桥接、不更改当前模型/预设、不为获取目录读取整份账号配置。

如果升级 ST 提示本地文件会被覆盖，那是被跟踪文件存在本地改动，不能靠升级千幕自动消除。请先备份并核对差异来源；例如明确标注其他插件名字的桥接补丁，需要按对应插件的升级方案处理。不要为通过更新而直接强制重置、删除补丁或忽略这些文件，否则可能丢失定制或使依赖该补丁的功能失效。

本仓提供隔离安装/升级回归及可选的 `scripts/check-st-upstream-compat.mjs`：后者只读取指定本地参考仓中的官方 1.19.0 标签并验证相关接口，不会更新实际运行的 ST。真实服务器的第三方组合、历史补丁与浏览器使用效果仍应在备份后单独验收。
