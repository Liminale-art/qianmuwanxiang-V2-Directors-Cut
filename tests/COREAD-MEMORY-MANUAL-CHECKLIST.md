# 伴读记忆实际阅读测试重点

> 2026-11-04 按 `refactor/storyboard-modularization` 的 `4c24a99e` 核对。以下是现行伴读的待验路径，不是已通过记录；真实长篇阅读、模型调用、跨端和实体手机需在明确范围内另验。
> 当前仍有本机伴读档案、可选世界书镜像和“从主线选择总结”。P5-A 计划调整这些数据边界，尚未整体落实；不得把此清单当作要求重新开发旧路线。忆幕只读关联已接入，但不等于伴读重构完成。

## 1. 总结质量与边界

- 连续阅读短章、长章、跨章时，自动总结的切分点是否自然，是否遗漏关键事实或重复复述。
- 自动总结与手动选择楼层总结交叠时，二次确认、覆盖范围和批次标识是否清楚且不误删未覆盖内容。
- 对同一范围进行二次总结后，原切片的来源、更新时间和旧版本追溯是否足够理解。
- 纯正文、正文夹对白、伴读短对话、漫画视觉文字稿分别验证默认提示词，不用单一模型的结果代替跨模型测试。
- 防全知剧透开启时，摘要、召回与回复都只能使用已读范围；关闭后也不得虚构未提供的后文。

## 2. 来源隔离与忆幕只读关联

- 正文形成的切片能否在书友对话中按当前问题召回，而不是只靠最近正文窗口。
- 伴读对话形成的总结能否在正文主线联动时命中，并能看出来源是“伴读对话”。
- 忆幕关联只消费用户明确允许的已确认记忆投影，不回写忆幕或 ST 正文；自定义切片需显式分享，混合阶段按整体边界隔离。未关联或未安装时，各模块仍独立工作。
- 世界书镜像和“从主线选择总结”属于当前遗留伴读路径；验证必须限定所选书籍／聊天，不能据“一套连续经历”自动共享其他聊天。P5-A 的移除／替换另按开发计划实施。
- 切换书籍、角色、用户人设、聊天文件后，记忆作用域是否严格隔离；重新绑定档案后共享召回是否符合预期。

## 3. 召回、向量与降级

- 编辑切片后同步向量化是否只更新目标记录；失败记录是否高亮、自动重试并可手动重试。
- 向量检索、重排、关键词锚定各自关闭或异常时，召回管线能否按预定顺序降级。
- 按当前代码分开核重试：伴读总结初次请求后最多 2 次重试，临时错误／格式问题会提示；向量和重排管线初次后默认最多 3 次重试，永久配置／鉴权错误立即失败，连续失败短暂熔断。不能概括为所有步骤都静默重试 3 次。真实测试按实际重试上限计入调用与费用。
- 上述属于伴读旧管线，不套用于忆幕；忆幕可选向量／重排的失败回退和当前成功链缺口见 [忆幕开发计划](../yimu/DEVELOPMENT-PLAN.md)。
- 召回或注入最终失败时，对话仍应正常生成，不得留下空白气泡、永久忙碌态或重复请求。
- 检索词典绑定、同义词扩展和无词典三种状态分别检查误召回与漏召回。

## 4. 存储、迁移与恢复

- 当前本机档案与用户开启的世界书镜像分别验证新增、编辑、删除和重开；镜像失败不能冒称档案未保存，也不能把本机 IndexedDB 当成天然跨端主库。未来 P5-A 改造后按新合同更新本项，不提前宣称镜像已删除。
- 伴读数据打包在同设备恢复及跨设备迁移后，书目、进度、正文缓存、图片、笔记、对话、切片、向量状态与绑定关系是否完整。
- 跨端只有书目、没有正文时补导原书，既有进度和记忆不能被重置或重复生成。
- 删除书籍且默认保留记忆后，重新导入同书能否重新关联；选择一并删除记忆时是否清理彻底。
- 浏览器清缓存、切换 ST 用户目录、插件热更新和意外中断后检查恢复路径。

## 5. 长期性能与稳定性

- 以高楼层聊天、长篇书籍、大量切片和大量图片分别测量首次打开、二次打开、切书、开伴读中心与发起召回的耗时。
- 检查千幕推演、配音缓存、伴读正文与向量索引是否按需加载，关闭阅读器后是否释放图片 URL、观察器和事件监听。
- 连续阅读与对话 1–2 小时，检查内存增长、重复气泡、重复总结、卡死和移动端发热。
- 弱网、API 超时、流式中断、切换模型、切换聊天和中途关闭抽屉时，确保任务可停止且状态不会污染下一次请求。

## 6. 模型差异与前端纯净度

- 用至少三类模型测试流式与非流式输出，确认思维链、行号、格式说明和后台协议不会泄漏到普通气泡。
- 总结模型返回空内容、非 JSON、半截 JSON、重复标签、超长文本时，检查解析、修复与错误说明。
- 伴读回复条数、字数、防剧透和身份约束在不同算力模型上均需满足；不能依赖单一模型“刚好听懂”。

## 通过标准

- 用户能在“注入状态”中解释本次实际带入了什么、来自哪里、哪一步命中或降级。
- 各路径按上述实际重试合同反馈，最终失败可定位且不阻断无关阅读；不把伴读总结现有重试提示误写成完全静默。
- 真实使用反馈确认总结质量后，再冻结默认提示词、批次覆盖策略与二次总结版本规则。
