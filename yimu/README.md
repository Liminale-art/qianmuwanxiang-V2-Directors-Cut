# 忆幕

独立、可选的 SillyTavern 单聊记忆扩展。当前候选版 **0.5.1**，须搭配 **忆幕服务端 0.5.1**；基本功能不依赖千幕增强服务。每份普通聊天初始关闭，不自动整理已有聊天。可选的伴读关联需要千幕 **1.59.483** 或更新版本。

## 安装与更新

安装和以后更新使用同一条命令，自动成对安装前端、服务端，保留旧文件。需要 ST 已有的 Node.js 18+、Git，以及可访问 GitHub 的网络。

### Linux / VPS（PM2）

将路径和服务名改成自己的；下面适用于 ST 位于 `/usr/local/games/SillyTavern`、PM2 名为 `sillytavern` 的环境。执行期间会短暂停止并重新启动这个 ST 服务，请先结束正在生成的聊天。

```bash
bash -c 'set -o pipefail; curl -fsSL https://raw.githubusercontent.com/Liminale-art/qianmuwanxiang-V2-Directors-Cut/refactor/storyboard-modularization/install-yimu.sh | bash -s -- --st-root /usr/local/games/SillyTavern --pm2 sillytavern'
```

### Windows 本地

先停止 ST 后端，在 **ST 文件夹**打开 PowerShell，粘贴：

```powershell
& ([scriptblock]::Create((Invoke-RestMethod 'https://raw.githubusercontent.com/Liminale-art/qianmuwanxiang-V2-Directors-Cut/refactor/storyboard-modularization/install-yimu.ps1'))) --stopped
```

完成后按原方式启动 ST。无需修改 PowerShell 的全局执行策略。

### 非 PM2 / 容器 / 自定义配置

先停止对应 ST 实例，再在其**实际持久化的 ST 根目录**执行 Linux 命令，将 `--pm2 sillytavern` 换成 `--stopped`。自定义配置另加 `--config 配置路径`，路径须在这个 ST 根目录内。完成后按原方式启动；容器的 `plugins` 和前端扩展目录也必须持久化，不要只安装进临时容器层。

安装器只处理 `plugins/yimu`、`public/scripts/extensions/third-party/yimu` 和必要的 `enableServerPlugins` 开关，不改聊天、账户资料或千幕。遇到已有手动安装、本地修改、不明确的运行路径会停下，不强行覆盖。不要同时安装全局版和账户版忆幕。

### 怎么确认生效

刷新 ST，从扩展入口打开**忆幕**。服务正常且配套版本为 **0.5.1** 才算运行成功；终端“文件已安装”不代表后台已加载。版本不一致先确认重启的是同一 ST，再刷新页面。安装保留目录为 ST 根目录下的 `.yimu-install-backups`。

## 开始使用

1. 打开一份单聊，进入忆幕并开启；首次确认整理范围，默认完整历史。建议先用另建的测试聊天或聊天副本。
2. 默认保留最近 **5 层原文**，可自行调整。后台按内容量分批整理，完成且来源有效的记忆从**下一次生成**使用，不阻塞正常聊天。
3. 可修订记忆、重新总结，或手动整理阶段摘要；自动阶段整理初始关闭，默认按 token 数触发，也可改为层数或切片份数。
4. **自动回查与补充（试用）**默认开启，之前关闭过的保持关闭。普通总结发现具体缺口时，才在相关细摘要对应的原文内核对；每轮后台整理最多额外抽取一次，可能产生一次模型调用费用。关闭后不再发起新回查。

默认沿用当前 ST 连接，也可选择独立连接与模型。总结和整理会调用模型，可能产生费用；失败不偷偷换模型，不连续重试或反复弹窗。关闭网页后不继续执行。

## 续接、分支与伴读

- 在 ST 打开要作为来源的聊天，进入忆幕的**故事续接与分支**。续接默认截至末尾，分支可选截止楼层；先核对范围，再明确创建并为新聊天开启忆幕。新文件只带设置数量的近期原文，以及截止前可继承的有效记忆。
- 跨过截止点的自动切片只用截止前原文重新整理，可能产生模型费用；手动修订和没有确定楼层的补充由用户选择，不自动裁剪或带入。尚未整理、已删除或停用的旧内容不会偷偷补回，界面会说明未继承范围。
- 新旧聊天独立发展，原聊天不变，不自动写回或同步。继承摘要保留来源关联、可手动修订；当前版本不跨故事自动重总结或追加原文引证。重复点击、结果未确认时按同一次操作核对，不盲目再建；此待确认操作保留在当前页面，关闭网页前应确认结果。
- **关联伴读**中选择明确的书籍、书友及 USER 档案，确认共同已读截止，再预览并确认摘要。旧本机档案需明确确认归属。翻页本身不算共同已读；书中背景和真实交流分开标注，未知来源、混合来源及未来片段不自动纳入。
- 关联只保存本次确认的有限摘要，不上传全书、不迁移伴读原档。摘要可随同账户忆幕跨端读取；更新范围需再次确认。正文与伴读只在精确关联的当前故事中使用有效记忆，分支不会自动继承活动关联。

## 备份与导入

在忆幕中展开**备份与导入**：

1. **导出当前记忆**：保存细摘要、阶段摘要、手动补充、修订历史、冲突与来源关联。**附带 ST 聊天原件**是单独选项，默认不勾选；需要时逐项选择主聊天和分支祖先原件。生成的是忆幕自己的压缩文件 `.yimu.gz`，不会另行收集 ST 连接密钥或模型连接配置；选中的聊天原件按原文件保留其已有内容与元数据。
2. **导入备份包**：点击**选择忆幕备份包**，核对已选文件名后再**确认上传备份包**。只接受忆幕自身格式，核对完整性后保存为当前 ST 账户的独立资料；首页也可操作。导入本身不创建聊天、不启用记忆，完全相同的包不会重复入库。记忆和保留的历史可直接查看。
3. **恢复为新聊天副本**：明确选择已有角色及包内原件，再确认恢复；原聊天和原记忆不覆盖，副本的忆幕默认关闭。未附主原件时，可打开一份已有聊天并明确选择用它核对，只有完整正文指纹一致才复制；不按角色名或文件名猜测匹配。

未附带或无法明确恢复的祖先来源会保持未核验，相关记忆不参与生成、回查或原文替换；手动修订与历史仍保留。伴读快照仅作为历史资料保存，不自动恢复活动关联。恢复聊天保留全部消息行，但不回灌旧聊天的插件设置或旧忆幕绑定；原始聊天文件仍完整保存在备份包中。角色卡、图片和音频等外部附件需另行备份。

大文件按块上传、解压和校验，不把整个聊天转成一份巨大的请求正文。网络中断或结果未确认时，界面可按同一次操作继续核对，避免重复创建；服务器或反向代理的上传容量、超时和可用磁盘仍适用。格式错误或不完整的包不会成为可恢复资料。

## 记忆与原文如何保全

- **日常记忆整理不改写现有 ST 聊天文件，也不另外复制一份完整原文。** 续接／分支只按明确操作新建聊天并复制近期衔接原文；备份与恢复仅在用户明确选择后携带或复制原件。原文补充仅保存楼层、指纹和引用位置；读取时从当前聊天核验还原。只能引用原段，不能凭模型返回编造来源。
- 补充是带说话者的**原文引证**，不是已证实的新事实或所有角色共同知情。来源、父摘要、开关或聊天状态变化，未完成补充直接放弃；人工修订和待处理冲突优先，不自动覆盖或换说法补回。
- 细摘要和阶段摘要保留来源关联。只有完整、有效且通过整份请求预算的记忆，才替换本轮请求中对应的旧原文；近期层、未整理层和未被采用记忆对应的原文不会被忆幕删除。引证自身不能删除整层原文。
- 安全替换目前支持主聊天纯文本 Chat Completion 的普通生成、重生成、滑动重生成。不明确的请求形态、来源映射或预算一律保留原请求。计数含保守估算，不是提供商精确计费承诺；其他扩展后续改写请求仍需单独核验。
- 当前人工修订或冲突存在时，自动原文补充会保守暂停，普通聊天及其他有效记忆照常使用。原文核验能防错源，不能保证模型对所有叙事的理解无误。

## 数据与回退

忆幕资料及导入档案保存在当前 ST 账户的 `.yimu` 下，跨设备访问同一 ST 账户可读取；不同 ST 实例不自动同步。当前使用 schema 5，旧 schema 1/2/3/4 只在首次实际写入前迁移，并保留逐字节一致的对应 `.schema1.bak` / `.schema2.bak` / `.schema3.bak` / `.schema4.bak`。打开面板不会主动迁移。

关闭聊天忆幕会停止其注入与后续整理，保留已有资料。降级前先完整备份 `.yimu`，不能只换旧程序后继续写新格式；升级前备份也不能覆盖升级后的新修订。卸载程序不删除聊天。

真实叙事质量仍需单独实测；首版不做群聊或第三方摘要自动转换。正式聊天不要同时启用多套自动记忆注入。

开发构建：`node scripts/build-yimu.mjs <不存在的输出目录>`。得到独立前后端，不混入千幕发行包。自动测试使用合成账户、聊天与模型返回；不代表真实叙事质量或所有部署环境已验收。
