# 忆幕 · 分层记忆单聊候选版

这是独立、可选的 ST 扩展，不依赖千幕运行，不自动启用任何聊天。当前版本 **0.2.0**，前端需配套 **忆幕服务端 0.2.0**；千幕增强服务不是这份服务端。

已实现每聊天启停、首次范围确认、后台分批细摘要、阶段整理、按需选择已存记忆、最终请求预算核对与原文替换，以及手动补充／修订／撤回／重总结、来源变化停用与同条跨端冲突保留两版。记忆在当前 ST 账户中保存；只记录摘要、修订和来源指纹，不再复制聊天原文。关闭网页不继续执行任务。

## 运行边界

- 仅单聊。每份聊天默认关闭；首次开启先确认起止楼层，近期原文默认 5 层。尚未处理的楼层不会被标为已覆盖。
- **从不修改 ST 聊天文件。** 仅在主聊天最终请求里，以完整、来源有效且已通过预算的记忆替换对应旧原文；未被选入的摘要所对应原文、未处理楼层和近期保留层不会被忆幕删除。先克隆请求、核对来源与整份预算，全部满足才一次性替换；任何一步不能确认便保持原请求不变。
- 当前安全替换支持 ST 主聊天的纯文本 Chat Completion 普通生成、重生成和滑动重生成。文本补全、继续生成、工具／多模态、额外结构字段、自定义正文改写、无法唯一匹配的重复内容或近期原文已被宿主裁掉等情况，保留 ST 原上下文，不冒险猜楼层。后续兼容须单独核对，不能以这份候选宣称全提供商支持。
- 预算使用当前 Chat Completion 的实际上下文设置和本轮回复预留，整份最终消息参与核对；记忆按完整条目选入，不截断人工文字。ST 的 token 接口可能返回估算，因此同时使用更保守的 UTF-8 字节界限与消息开销；这可能少选记忆，但不是提供商精确计费或任意模型的绝对上限承诺。预算不够不先删原文。界面的最近使用记录仅表示已核对的待发请求，不代表模型已接收。
- 总结触发初值 4000 token，内部批次最多约 6000 token，并受当前连接上下文约束；近期原文、触发阈值、注入预算和偏好可按聊天覆盖账户默认。这里的 token 估算不是提供商账单。
- 默认使用当前 ST 连接；可选择连接管理器中的独立连接和模型。不切换 ST 全局连接，也不在失败后偷偷换模型。开启或手动整理会调用所选模型，可能产生费用。
- 自动整理失败不反复弹窗或连续重试；顶部保留事实提示，可主动重试。保存未确认不报成功；来源失效的旧记忆不会因为整理失败重新启用。
- 阶段摘要保留底下的细摘要。可手动选择完整细摘要区间，或开启后台自动整理，依据 token／原文层数／切片份数三选一。自动阶段整理初始关闭，默认依据 token，初始阈值 6000；只统计尚未整理的有效细摘要，不反复统计整段历史。人工修改的细摘要不进入自动二次压缩；阶段来源有变化立即失效，失败不恢复旧阶段。
- “按需回查细摘要”初始开启：根据近期实际叙事，对已保存细摘要和阶段摘要做相关性选择；需要特定细节时选细摘要，不把同一来源的两层摘要重复塞入。此步骤不额外调用模型、不生成新的故事事实，也不能绕过人工修订、删除或暂不使用。它不是语义理解或零幻觉保证。
- 原文级追加补充、故事续接／分支、伴读关联、自有备份包仍属后续节点，**不属于本候选已完成能力**。当前不转换第三方摘要；请勿与其他自动记忆注入扩展同时用于正式聊天。

这些核对只保证忆幕提交时的 ST 请求。忆幕把自身核对放到原生事件链末端，但无法阻止之后新注册的第三方处理再次改写消息；与其他请求改写扩展共存仍需单独验收。

## 构建与安装（不自动执行）

在仓库运行 `node scripts/build-yimu.mjs <一个尚不存在的输出目录>`，得到两个独立目录：

1. `frontend/yimu`：复制到 ST 的 `public/scripts/extensions/third-party/yimu`（全局），或 `data/<当前账户>/extensions/yimu`（仅该账户）。不要同时装两份。
2. `server/yimu`：复制到 ST 的 `plugins/yimu`。由管理员在 ST 配置中启用原生服务器插件支持后重启 ST；浏览器刷新扩展。

不修改 ST 本体、不另开端口、不猜数据路径。服务端使用 ST 为当前请求提供的账户目录，因此本地、VPS、容器和自定义数据目录走同一机制。容器须保留原 ST 数据卷，插件目录也需按原部署方式持久化；只写的账户目录才能保存。

后端版本与前端不一致时，面板明确显示配套要求，不退回浏览器保存并冒称跨端成功。安装后应先在合成聊天或另建聊天副本启用，不在正式聊天上试错。当前源码接口核对基于 ST **1.18.0 / 8172dcd**；ST 1.19、真实 VPS、实体手机及实际模型摘要质量仍须单独验收。源码检查和合成测试不等于这些环境已通过。

## 数据与回退

资料放在当前 ST 账户目录下的忆幕专属子目录，含账户默认设置与每聊天文件。源聊天仍是 ST 自身 JSONL。文件条件写入、来源核对、操作凭据和短文件锁用于防止旧页面覆盖新资料；损坏文件、异常链接或遗留锁不会被自动清除。

本版本使用资料格式 schema 2。读到 0.1.0 的 schema 1 仅在内存解释，不因打开面板就改旧文件；第一次实际写入前保留字节一致的 `.schema1.bak`，再写新格式。备份已存在却与原旧文件不一致时停止迁移，不覆盖。此备份只代表升级当时状态，不包含升级后的修订。

关闭当前聊天忆幕即可停止该页注入与后续整理，保留已有记忆。卸载前端／服务端不会删除 ST 聊天。需要降回 0.1.0 时，先停用并完整备份当前账户的 `.yimu`，再由管理员核对恢复旧格式备份；不能只换旧程序后继续写 schema 2，也不能以升级前备份覆盖另一设备的新修订。跨 ST 实例不是自动同步；本候选尚无备份包导入导出界面。

## 开发验证

`node --test tests/yimu-*.test.mjs`（在支持通配展开的终端运行；PowerShell 可先获取文件列表再传给 node）。全部用合成账户和模型返回夹具，不调用付费 API。候选构建与千幕发行白名单分离，不会混入当前千幕发行包。
