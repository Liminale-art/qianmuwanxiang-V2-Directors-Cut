# 忆幕

独立、可选的 SillyTavern 单聊记忆扩展。当前版本 **0.7.0**，须搭配 **忆幕服务端 0.7.0**；基本功能不依赖千幕增强服务。每份普通聊天初始关闭，不自动整理已有聊天。可选的伴读关联需要千幕 **1.59.483** 或更新版本。

本次新增双开关与范围整理，存储格式升级为 **schema 6**。前后端版本须一致，请使用下方一键更新；不需要重新导入已有记忆。

## 安装与更新

安装和以后更新使用同一条命令，自动成对安装前端、服务端，保留旧文件。需要 ST 已有的 Node.js 18+、Git，以及可访问 GitHub 的网络。

### Linux / VPS（PM2）

将路径和服务名改成自己的；下面适用于 ST 位于 `/usr/local/games/SillyTavern`、PM2 名为 `sillytavern` 的环境。执行期间会短暂停止并重新启动这个 ST 服务，请先结束正在生成的聊天。

```bash
bash -c 'set -o pipefail; curl -fsSL https://raw.githubusercontent.com/Liminale-art/qianmuwanxiang-V2-Directors-Cut/refactor/storyboard-modularization/install-yimu.sh | bash -s -- --st-root /usr/local/games/SillyTavern --pm2 sillytavern'
```

### Windows 本地

先停止 ST 后端，在 **ST 文件夹**打开 PowerShell，粘贴：

```powershell
& ([scriptblock]::Create((Invoke-RestMethod 'https://raw.githubusercontent.com/Liminale-art/qianmuwanxiang-V2-Directors-Cut/refactor/storyboard-modularization/install-yimu.ps1'))) --stopped
```

完成后按原方式启动 ST。无需修改 PowerShell 的全局执行策略。

### 非 PM2 / 容器 / 自定义配置

先停止对应 ST 实例，再在其**实际持久化的 ST 根目录**执行 Linux 命令，将 `--pm2 sillytavern` 换成 `--stopped`。自定义配置另加 `--config 配置路径`，路径须在这个 ST 根目录内。完成后按原方式启动；容器的 `plugins` 和前端扩展目录也必须持久化，不要只安装进临时容器层。

安装器只处理 `plugins/yimu`、`public/scripts/extensions/third-party/yimu` 和必要的 `enableServerPlugins` 开关，不改聊天、账户资料或千幕。遇到已有手动安装、本地修改、不明确的运行路径会停下，不强行覆盖。不要同时安装全局版和账户版忆幕。

### 怎么确认生效

刷新 ST，从聊天菜单打开**忆幕**，在**设置**页查看服务状态。服务正常且配套版本为 **0.7.0** 才算运行成功；终端“文件已安装”不代表后台已加载。版本不一致先确认重启的是同一 ST，再刷新页面。安装保留目录为 ST 根目录下的 `.yimu-install-backups`。

## 界面入口

- **概览**：启用忆幕、选择自动或手动总结，查看记忆切片、已整理层与待整理层。
- **记忆**：搜索、筛选和修订记忆切片，添加手动补充，整理阶段摘要。
- **设置**：调整近期原文、整理条件、连接与模型，以及输入栏快捷入口。

**记忆调阅、故事续接、关联伴读、记忆备份**在概览就地展开，可同时展开多项。记忆调阅保留最后一次实际加入生成请求的记忆快照与估算用量，不把候选列表当作已使用，也不声称模型已接收。切页或收起保留未提交内容；切换聊天后重新核对来源。

## 开始使用

1. 打开单聊，在概览开启**启用忆幕**。**自动总结**是独立开关；关闭自动仍可使用已有记忆和手动总结，关闭忆幕则全部停止，资料保留。新聊天的两个开关初始均关闭，旧版已开启的聊天保留原先自动行为。首次可确认“是否整理历史楼层”，取消后不再询问，之后用手动总结补充。
2. 默认保留最近 **5 层原文**，可自行调整。后台按内容量分批整理，完成且来源有效的记忆从**下一次生成**使用，不阻塞正常聊天。
3. **手动总结**填写起止楼层后开始；成功且来源有效才替换该范围的自动切片。手修版保留，新结果供选择；失败的部分保留旧记忆。只截到旧切片一部分时，先显示完整范围，再点开始确认，不会悄悄扩大读取范围。已删除或暂停的切片先恢复或调整范围。ST 隐藏正文仍可总结，不改隐藏标记；即使手动整理了近期层，生成时仍保留设置数量的近期原文。
4. 可修订记忆，或手动整理阶段摘要；自动阶段整理初始关闭，需同时开启自动总结，默认按 token 数触发，也可改为层数或切片份数。
5. **自动回查与补充（试用）**默认开启，之前关闭过的保持关闭。普通总结发现具体缺口时，才在相关记忆切片对应的原文内核对；每轮后台整理最多额外抽取一次，可能产生一次模型调用费用。关闭后不再发起新回查。

默认沿用当前 ST 连接，也可在**设置 → 整理 API**选择 ST 已存连接，或独立填写 URL、Key、模型与容量；支持拉取模型、流式接收和保存预设。免 Key 的本地服务可留空。测试连接只检查模型目录接口，不执行总结或证明生成成功。独立连接配置与密钥保存在 ST 账户设置，不进入忆幕记忆文件或备份包。

总结和整理会调用模型，可能产生费用；失败不偷偷换模型，不连续重试或反复弹窗。关闭网页后不继续执行。

整理兼顾事实与叙事质感：保留有意义的情绪过程、动作／对白和场景气氛，不将经历压成人物档案，也不为文学化补造心意或情节。阶段整理沿用同一原则；正文以当前场景和近期原文的文风为准，不模仿摘要的简写腔。更新不会自动改写已有切片或手动修订，实际文学效果仍需模型实测。

ST 聊天菜单中的“忆幕”入口始终保留。输入栏快捷入口默认隐藏，可在**设置**中开启**显示输入栏快捷入口**；此开关只控制入口显示，不会开启聊天记忆。快捷图标正常为灰蓝、执行失败为灰红，未启用或尚未就绪等其他状态为纯灰，悬停可查看具体状态。

## 续接、分支与伴读

- 在 ST 打开来源聊天，从**概览 → 故事续接**进入。续接默认截至末尾，分支可选截止楼层；先点**预览带入内容**，再明确创建并为新聊天开启忆幕。新文件只带设置数量的近期原文，以及截止前可继承的有效记忆。
- 跨过截止点的自动切片只用截止前原文重新整理，可能产生模型费用；手动修订和没有确定楼层的补充由用户选择，不自动裁剪或带入。尚未整理、已删除或停用的旧内容不会偷偷补回，界面会说明未继承范围。
- 新旧聊天独立发展，原聊天不变，不自动写回或同步。继承摘要保留来源关联、可手动修订；当前版本不跨故事自动重总结或追加原文引证。重复点击、结果未确认时按同一次操作核对，不盲目再建；此待确认操作保留在当前页面，关闭网页前应确认结果。
- 从**概览 → 关联伴读**进入，选择对应记录与**共同已读位置**，再预览并确认摘要。旧本机记录需明确确认归属。翻页本身不算共同已读；书中背景和真实交流分开标注，未知来源、混合来源及未来片段不自动纳入。
- 关联只保存本次确认的有限摘要，不上传全书、不迁移伴读原档。摘要可随同账户忆幕跨端读取；更新范围需再次确认。正文与伴读只在精确关联的当前故事中使用有效记忆，分支不会自动继承活动关联。

## 备份与导入

从**概览 → 记忆备份**进入：

1. **导出当前记忆**：保存记忆切片、阶段摘要、手动补充、修订历史、冲突与来源关联。**同时备份聊天记录**默认不勾选；需要时逐项选择当前聊天和分支来源。生成忆幕压缩文件 `.yimu.gz`，不会另行收集 ST 连接密钥或模型连接配置；选中的聊天记录保留原文件内容与元数据。
2. **导入备份包**：点击**选择忆幕备份包**，核对文件名后再**确认上传备份包**。只接受忆幕自身格式，核对完整性后保存在当前 ST 账户的**已导入备份**中；未打开聊天时也可操作。导入不会创建聊天或启用记忆，相同的包不会重复入库。记忆和修订历史可直接查看。
3. **找回聊天**：选择已有角色及包内聊天记录，点**确认找回聊天**；另建聊天，不覆盖原聊天和原记忆，忆幕默认关闭。未附当前聊天记录时，可打开一份已有聊天并勾选**使用当前聊天作为原文**，只有完整正文指纹一致才复制，不按角色名或文件名猜测。成功后点**打开找回的聊天**。

未附带或无法核对的分支来源不会自动启用，相关记忆不参与生成、回查或原文替换；手动修订与历史仍保留。伴读摘要仅作为历史保存，需重新确认关联。找回聊天保留全部消息，但不带回旧聊天的插件设置或忆幕绑定；原始聊天文件仍完整保存在备份包中。角色卡、图片和音频等外部附件需另行备份。

大文件按块上传、解压和校验。网络中断或结果未确认时，可继续同一次操作，避免重复创建；服务器或反向代理的上传容量、超时和可用磁盘仍适用。格式错误或不完整的包不会成为可用备份。

## 记忆与原文如何保全

- **日常记忆整理不改写现有 ST 聊天文件，也不另外复制一份完整原文。** 续接／分支只按明确操作新建聊天并复制近期衔接原文；备份与恢复仅在用户明确选择后携带或复制原件。原文补充仅保存楼层、指纹和引用位置；读取时从当前聊天核验还原。只能引用原段，不能凭模型返回编造来源。
- 补充是带说话者的**原文引证**，不是已证实的新事实或所有角色共同知情。来源、父摘要、开关或聊天状态变化，未完成补充直接放弃；人工修订和待处理冲突优先，不自动覆盖或换说法补回。
- 记忆切片和阶段摘要保留来源关联。只有完整、有效且通过整份请求预算的记忆，才替换本轮请求中对应的旧原文；近期层、未整理层和未被采用记忆对应的原文不会被忆幕删除。引证自身不能删除整层原文。
- 安全替换目前支持主聊天纯文本 Chat Completion 的普通生成、重生成、滑动重生成。不明确的请求形态、来源映射或预算一律保留原请求。计数含保守估算，不是提供商精确计费承诺；其他扩展后续改写请求仍需单独核验。
- 当前人工修订或冲突存在时，自动原文补充会保守暂停，普通聊天及其他有效记忆照常使用。原文核验能防错源，不能保证模型对所有叙事的理解无误。

## 数据与回退

忆幕资料及导入档案保存在当前 ST 账户的 `.yimu` 下，跨设备访问同一 ST 账户可读取；不同 ST 实例不自动同步。当前使用 schema 6，旧 schema 1/2/3/4/5 只在首次实际写入前迁移，并保留逐字节一致的对应 `.schema1.bak` / `.schema2.bak` / `.schema3.bak` / `.schema4.bak` / `.schema5.bak`。打开面板不会主动迁移。

关闭聊天忆幕会停止其注入与后续整理，保留已有资料。降级前先完整备份 `.yimu`，不能只换旧程序后继续写新格式；升级前备份也不能覆盖升级后的新修订。卸载程序不删除聊天。

真实叙事质量仍需单独实测；首版不做群聊或第三方摘要自动转换。正式聊天不要同时启用多套自动记忆注入。

开发构建：`node scripts/build-yimu.mjs <不存在的输出目录>`。得到独立前后端，不混入千幕发行包。自动测试使用合成账户、聊天与模型返回；不代表真实叙事质量或所有部署环境已验收。
